## How the site works
* Quarto website. Student-facing only; Maurice's own planning lives in Notion, private files in Drive.
* **Schedule data is kept once** in `data/ski3010.yml`, `data/ski3011.yml`, `data/pro3017.yml` (weeks, lecture/tutorial items, quizzes, assignments with deadlines, homework, assessment table). `scripts/build.py` generates from it: `<module>/schedule.qmd`, `<module>/week-N.qmd`, `<module>/_weeks.qmd` (week cards), `<module>/_assessment.qmd`, `deadlines.qmd` and `calendar.ics`. These generated files are in .gitignore; never edit them by hand.
* Handwritten pages: `index.qmd` (home), `<module>/index.qmd` (start here), `<module>/syllabus.qmd`, `submit.qmd`, `tools.qmd`, `rubrics.qmd`, `ai.qmd`, and per week `<module>/_concepts-week-N.qmd` (concept list + practice questions, included in the week page when present).
* Downloads: put files in `materials/<module>/week-N/`; the week page lists them automatically.
* `assets/thisweek.js` highlights the current week and greys out past deadlines. Styling in `styles.scss`, navigation and sidebars in `_quarto.yml` (week pages listed explicitly per module: add a line when a week is added).
* Render locally: `python3 scripts/build.py && quarto render` (needs PyYAML: `python3 -m pip install --user pyyaml`). Quarto resolves includes before its pre-render step, so on a clean checkout the build script must run first; the workflow does this.
* Every push to `main` triggers `.github/workflows/publish.yml` (build script, render, deploy to GitHub Pages, build type "workflow"). Custom domain ucm.meta-research.nl is set in the Pages settings, not with a CNAME file. DNS at mijndomein.nl: CNAME `ucm` -> `mauricezeegers.github.io`.
* **R lectures in Quarto (SKI3011, since 2026-10-08):** one `ski3011/r-lecture-N.qmd` per lecture gives a web page (explanation + code + real output) and, via `scripts/qmd_to_r.py`, a downloadable R script in which all text is comments and `##` headings are RStudio sections. Maurice's lecture IS running this script line by line, so no slides (decided 2026-10-08). Line explanations go as ordinary R comments in the code (no code-annotations), so they end up in the script. `execute: freeze: auto` in `_quarto.yml`: R runs only locally, results in `_freeze/` (committed), so CI needs no R. After editing a lecture run `scripts/render-r-lectures.sh` (renders it and writes the student script to `materials/ski3011/week-N/r-lecture-N.R` with scripts/qmd_to_r.py). Link it from the week via `links:` in `data/ski3011.yml` ; R lectures are NOT in the sidebar (Maurice, 2026-10-08), only linked from the week pages. Weeks 2-6 converted on 2026-10-08 (all scripts tested with Rscript). Datasets: week 2 ETS-bladder (11 studies, same as the SKI3010 exercise, study 'Zeegers 2002' renamed 'NLCS') + bcg.csv practice file; week 3 bcg, hannum2020, molloy2014; week 4 collins1985b, hackshaw1998, TLIF/PLIF inline, normand1999; week 5 bcg, egger2001; week 6 bcg, hannum2020, bangertdrowns2004.
* Datasets used in the SKI3011 paper quizzes (dat.lau1992, dat.mcdaniel1994, dat.baskerville2012) must never appear on the site; lectures and practice use other datasets (bcg, hannum2020, molloy2014, normand1999).
* Preview in the Codex desktop browser pane: the preview server cannot read Google Drive, so `.Codex/launch.json` (in the parent folder) serves a copy of `_site/` from the session scratchpad; rsync `_site/` there after each render.
